# 人物倒向滑行与闪变修复 · 2026-09-16

本轮定位真实工程并检查当前源码与前次包哈希。工程无 Git，未伪造提交。只修改人群运动朝向、NPC 动画/远景表示与现有 LOD 网格，不改变玩家移动、相机、碰撞半径、地标、任务和存档，不调用 Tripo 或其他付费生成 API。

## 原因与挂接

1. `src/crowd-motion.js` 的普通路径分支把路线切线 `angle` 写回人物；绕行回归路径时，实际位移可能仍朝侧面或反方向。现在每次运动更新结束后，以实际接受的净位移计算 NPC 朝向；停步不强行改朝向，动画仍按实际位移切换。
2. `src/npc-assets.js` 原来在距离 28 处直接切换完整骨骼模型与静态实例。边界轻微来回会反复切换，动作姿势也瞬间变成静态。现在同一个角色实体、同一套骨骼与动作，只切几何精度；32 以外切远景、24 以内才切回近景。远景不再使用静止人物沿路平移。
3. 原 LOD 制作使用 `simplifySloppy`，目标只有约 10% 三角面，并未将 UV、法线与蒙皮权重纳入简化误差。近远景对比发现纹理破碎、外观突变。新增 `scripts/repair-npc-lod.mjs`，使用带属性误差约束的本地简化并锁定边界；目标比例 40%，允许因误差约束保留更多面。45 个原始人物 GLB 和已有动作均保持 SHA-256 不变，只替换派生 `.lod.glb` 和更新 catalog 的 LOD 字段。旧 LOD 和 catalog 已备份。
4. 动画降频时，原实现先提前 return 再累计 dt，可能使动作比位移慢。现在每次更新累计动画时钟与混合权重，远景仍以 10Hz 采样骨骼姿势；近景 30Hz。职业动作也做权重过渡。远景沿用原先不投射动态阴影的策略。

运行文件：`src/crowd-motion.js`、`src/npc-assets.js`、`src/street-life.js`（渲染状态标签）。新增回归：`src/npc-assets.test.js`，追加 `src/crowd-motion.test.js`。

## 限制与性能

同一观察镜头最后一帧，原版约 18 FPS、873 draw calls、6,900,618 三角面；最终版约 14 FPS、918 draw calls、7,628,244 三角面，65 人可见，其中 42 人采用可动远景。是真实场景单点读数，非严格性能基准。保留真实动作与更完整网格增加开销，现阶段不能宣称流畅度或 60 FPS 验收通过。后续优化需要保持动作与外观一致，不能退回静止远景滑行。

未验证手机/Safari、所有远景角色逐帧视觉效果、长时间全图巡游或完整新档通关；不冒充真人试玩。开场演出按之前要求未测试。
