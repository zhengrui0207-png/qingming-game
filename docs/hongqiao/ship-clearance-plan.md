# 船节点与净空验证计划

## 已检查的真实结构

`public/assets/qingming-world.glb` 是 24 个按材质合并的静态网格，无骨骼、无动画。大船不具备独立可移动根节点。不能移动 QMV4_static_QM_wood 一类节点来“移动船”，那会连街市木构一起移动。

`blender/landmarks_v4.py` 和 `.dream-loop/landmarks-v4-report.json` 记录原生船由 10 个网格组成（原船 4 个与细节网格），位置中心约 X=18、Z=-3。原生工程优先检查 `blender/汴河入画-v4.1.blend`，其中 `QMV3_cargo_landmark_*` / `QMV4_barge_detail_*` 是拆分线索。脚本记录不是已经检查 Blender 当前对象状态的证据。

现有报告全船包围盒：X=[8.00024,27.99976]、Y=[-0.41939,10.03148]、Z=[-9.36994,3.03200]。world.json 中船碰撞代理中心为 [18,-3.16897]，宽约20.50、深约12.90。桥最高行走面约8.24；当前高桅与船体不能直接假定能通过。

## 本步候选路径

临桥 [22,0,-3.16897] → 止进 [18,0,-3.16897] → 等待 [18,0,-3.16897] → 通过 [-18,0,-3.16897]。以现有船障碍代理中心作为未来根节点约定；Y=0 是河面资产基准，不是所有顶点贴水。

临桥4单位接近，止进和等待无瞬移。候选路径只是基于现有船位和桥方向的连续空间预留，本步未移动原船。通过位置在船体 X 半长之外预留桥宽；最终数值须按拆分后的真实根节点和船体扫掠重测。

## 拆分后必须验证

1. 保存原件，将船体、船员、货物挂在独立船根节点；原静态导出移除对应几何，不能叠船。
2. 桅杆、支承、帆和索具分组，真实转轴降桅；检查完整摆动体积和货棚、船员、货物、桥体的交叠。
3. 实测顶杆两端与船员站位；桥上两处抛绳点分别记录，明确留在桥上的握持端、船上接应端。岸上纤夫路线与纤绳起终点独立，不借用任务盘绳。
4. 沿路径每0.25单位采样船体/低桅/索具/船员的世界包围体，并针对桥梁真实网格做窄相检测。检查桥洞两侧与最低梁底，不用桥面高度替代净空。
5. 检查与背景游船、码头及玩家小舟的关系；既有航行行为不能未经评估就改道。
6. 浏览器取临桥、接触、降桅中、等待、桥洞中心、驶出六组截图。失焦/跳过/恢复对应的终态留给 Step 7 验证。

顶杆/收杆、船头调向、牵行/松绳、两次抛绳/接绳/收绳、降桅属于专用动作需求。当前只有通用人物原型与静态船，不能以 idle/walk 或字幕视为通过。本步未运行 Blender 改模、Tripo 或动作制作。
