## Step 7 实现

- 已有 QMSH-22 船工复用于顶杆、调向、纤夫、桥上示警、抛绳与接应，采用手工关键帧和手部接触点 IK；没有重生成书生或船工，没有用通用 idle/walk 冒充这些专用动作。恰好两根接应绳，分别在 17.3 / 18.1 秒抛出；20–21 秒松纤绳、21–25 秒降桅、25–27 秒收杆收绳。
- 开场船从 x=14 连续临桥止于 x=10.3，再在降桅段连续退让至等待位 x=11。结束/任意跳过共用 finishIntro；不授予任务物、不接受任务、不解锁长故事。最后三秒只暂时隐藏挡住书生—老周视线的街市群演，结束恢复显示，不移动这些人的日常路径或位置。
- HQ_41 唯一交付事务完成后才进入 20 秒结尾，同船从 x=11 至 x=-16，低桅杆、人物和护货布随船。布使用独立陈设 ID，不注册成拾取物。完整船体已离开桥洞才进入 passed。
- 开场临时相机保存/恢复平时游戏相机及控制参数；跳过和结束等待旧键释放。结尾默认自由相机，可选“观看过桥”，结束/跳过/失焦恢复。使用现有 locks、gate 和整体存档，没有另造 EventBus。

1. 67 项纯状态、任务、演出、世界、移动及交互测试通过；生产构建成功。保留已有的大于 500 kB 包体提示，没有为消除提示重构工程。
2. Chrome 两段完整实时播放：开场 30 秒九镜全部访问，结尾 20 秒实际位移。九个跳过点使用开发 seek 定位后真实按 Esc/按钮，分别验证按住 E 的释放屏障。完整播放没有通过 seek 代替时长。
3. 21 项浏览器检查通过：九镜跳过、真实跨标签失焦及音轨暂停、开场刷新、四种旧档、正式“交给您”入口、交付后已持久化的四故事权限、可选镜头、收尾/分页阅读、两段回顾、结尾刷新及重复 UI 事件。Console / pageerror / HTTP 失败 / requestfailed 的最终记录均为空。
4. Blender 使用真实船体/货棚/桅杆三角形，加上人物、布、支承与收杆的保守外包络；62 个临桥样本、81 个降桅样本、109 个过桥样本，共 252 次三角形相交检查，0 相交。是离散路径及摆动检查，不宣称连续碰撞求解或真实古船力学。
5. 28 项既有交互回归通过，包括菜单/阅读分层输入锁、E 门闩、焦点、地标 F、移动和相机拖动。这个完整回归发生在之后的人物历史卡新改动之前；该并行功能不由本步验收。
6. 脚店实际浏览器检查：全景与伙计近景、两根筷子和碗的位置、F 打开脚店历史、I 开关、门前四方向按键行走、刷新后相同实例状态，以及不带 test 的普通入口。任务与背包没有因观赏店铺变化。实际录下零 Console / Network 错误；定位和特写使用 DEV 相机，不冒充从出生点手走全程。
7. 最后一轮 1280×800 Chrome 自动化实时样本：开场约 20.5 FPS、结尾约 22.1 FPS，最大帧间隔约 106 / 110 ms；开场样本约 509 万三角形/765 draw calls，结尾约 446 万/501。此前一轮同脚本约 60 FPS，说明运行环境负载与浏览器渲染条件存在波动，本轮尚不能签署流畅度验收。具体墙钟、帧间隔、设备与各帧状态保存在证据中；不能据此保证低端设备流畅。

初次阅读测试假设长页必须产生 scrollTop，遇到并行任务的分页正文而失败；随后按实际 UI 改为滚轮不改变相机、可滚动页验证滚动、短页验证翻页，并重新完整通过。门前某一个方向曾被正常人群碰撞阻挡，改为记录四方向的实际位移而没有放宽或删除碰撞。错误尝试与最终结果分开记录。
